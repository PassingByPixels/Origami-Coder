## What's new since 0.4.175

This version brings everything we built since 0.4.175, our last public release. The four big changes:

- **Elastic engines**: a chat that you do not look at uses much less memory and CPU, and a new chat is ready faster.
- **Plan mode works**: the plan agent writes a plan and asks you to approve or revise it.
- **A new agent map**: all your sub-agents, at every depth, live.
- **Drop to attach**: drop a file from the VS Code explorer on the composer to attach it.

### Elastic engines: hidden chats cost close to nothing

Each chat still has its own engine, so one chat cannot stop or slow another. What is new: the engine of a chat that you do not look at now gives back what it does not need.

{{diagram:engine-isolation|Why one engine per chat: with one shared engine, a hang stops every chat. In Origami, a failure stays in its own chat, and each chat has its own priority.}}

- **Active**: the chat you work in runs at normal priority.
- **Background**: a hidden chat runs at a lower CPU priority. Its work continues.
- **Idle**: a chat that is hidden and quiet for 5 minutes (the default) gets the lowest priority. On Windows, its memory is also trimmed. With 6 big idle chats, their memory in use fell from 2.63 GB to 0.57 GB, and their CPU use from 28-51 to 5-14 ms per second. <!-- source: CHANGELOG 0.4.176 and soak_elastic.md section 4 (working set; private bytes do not drop) -->
- **Parked**: at your "Park idle chats after" time, the engine process stops and its memory is free. The chat stays. Your next message, a handoff from another desk or a Folds prompt starts the engine again in the same chat.
- A parked chat that starts again sends the same bytes as before, so a prompt cache that is still warm still hits. A park does not break the cache.
- A chat that is on screen, runs a turn, or waits for your answer is never parked.
- **Warm spare**: each window keeps one engine ready, so a new chat is ready in about 0.5 seconds instead of about 1.3 seconds. The spare uses about 360 MB of memory per window. You can turn it off. <!-- source: soak_elastic.md "Warm spare" (495 vs 1,331 ms, medians); 360 MB: CHANGELOG 0.4.181 -->
- With five busy chats, the longest freeze of the chat on screen fell from 172-468 ms to 25-51 ms. The git snapshot and the Storage scans now run off the engine's main thread. <!-- source: CHANGELOG 0.4.176 and soak_elastic.md section 3.1 (6 runs per build) -->
- A closed chat frees its engine memory: about 200 MB less kept per closed big chat. A failed request no longer keeps about 180 MB after its chat closes. <!-- source: 200 MB: CHANGELOG 0.4.176; 180 MB: CHANGELOG 0.4.177 -->
- A window reload opens hidden chats without their engine. Each engine starts when you first focus its chat or send a message.
- When an engine does not start, the card tells you why (exit code, no answer in 60 seconds, or the engine's error), with Copy details and Open engine log. <!-- source: CHANGELOG 0.4.177 -->
- The **Origami Elastic** log shows each change of a chat's engine, and says "closed" when you close a chat.

On macOS, only an idle chat gets a lower priority, and there is no memory trim. Parking is what frees memory on macOS.

### Settings → Engines

- **Settings → Engines** holds all the engine settings: Elastic engines, Warm spare, Idle after, Park idle chats after, and the park time for providers with no published cache life. Most changes apply at once. The warm spare change applies from the next new chat.
- A **timeline** shows what happens to one chat after you leave it, with your values: background, idle, trim, park, and a mark for each cache warm.
- **New park defaults.** "Park idle chats after" is now 20 minutes (it was 60). The park time for providers with no published cache life (local servers, DeepSeek, OpenRouter) is now also 20 minutes (it was 120). <!-- source: lead instruction for 0.4.184 (defaults change in this release; not yet in CHANGELOG) -->
- If you still have the old defaults (60 and 120), Origami changes them to 20 one time. A value that you set yourself stays.
- Settings that are fixed when a chat starts say so: new chats get the change at once, and open chats keep their value.

### Cache warming: fixed, and now off by default

- Before this version, cache warming did not work: because of a bug, every warm failed and nothing was sent. <!-- source: CHANGELOG 0.4.183 -->
- Now, when the setting is on, each warm really goes out. **Each warm uses tokens**: it is a cache read at the provider's price.
- For this reason, **"Keep the prompt cache warm" is now off by default.** If you never changed it, it is now off. If you turned it on, it stays on. <!-- source: lead instruction for 0.4.184 (owner decision; not yet in CHANGELOG or package.json) -->
- Turn it on in Settings if you often come back to an idle chat within the cache life. New chats use the change at once.
- With cache warming on, a parked chat wakes in the background one minute before its warm is due, sends the warm, and parks again. The Origami Elastic log shows "woken to warm", "warmed" and "parked again". <!-- source: CHANGELOG 0.4.183 -->
- With cache warming off, a parked chat stays parked until you use it.

{{diagram:park-warm|With cache warming on (it is off by default), a parked chat wakes, sends one warm and parks again. Each warm uses tokens.}}

### Plan mode

- Plan mode now works. The plan agent writes a plan file and ends with the review, where you approve or revise the plan.
- If a model answers in plain text, the engine reminds it one time to finish the plan. A **Review as plan** button turns such an answer into the plan review.
- The plan-mode banner is gone. The **Plan** chip on the composer shows that plan mode is on.

{{diagram:plan-mode|Plan mode: the plan agent writes the plan, and you approve or revise it. A plain-text answer gets one reminder, and Review as plan turns it into the review.}}

### Agent map

- The agent map has a new look: a dot grid, one column for each level of sub-agents, each sub-agent on the row of its parent, with connecting lines, counts, and chips for background shells.
- It opens in the middle of the panel at a moderate size, fitted to the width. You can pan and zoom.
- It updates live for sub-agents at every depth, and shows the background shells that sub-agents start.
- The sub-agents pull-out and the agent map use one card.

{{diagram:agent-map|The agent map: one column for each level, each sub-agent on the row of its parent, with chips for background shells.}}

### Drop to attach

- Drop a file from the VS Code explorer on the composer to attach it. Images and text files attach.
- For any other type of file, the drop puts its full path in the message as text. A warning tells you that the path was added.
- The drop overlay always goes away when a drag ends, wherever it ends.

{{diagram:drop-to-attach|Drop from the VS Code explorer: an image attaches as an image, a text file as a file chip, and any other file adds its full path.}}

### Tool rows and prompts: a new look

- All tool rows have one look: line icons, a result badge, and a moving line only while the tool runs.
- **Edit** shows the diff split or unified, with aligned lines. **Grep** groups its matches by file, with links to the lines. **Read** and **Shell** show a bar with the file or the command.
- Questions open in the middle, one at a time. A question with more than one answer says "tick all that apply".
- Permission requests come up as one tray above the composer.
- The side quests and Browser pull-outs fold like the other rails. Browser shows a strip of its frames.

### Claude (Sub)

- Each subscription model shows one time in the model picker, as "Claude (Sub)/" and a readable model name, for example "Fable (1M context)".
- The picker lists Fable when your account has it.
- The usage line shows your usage instead of staying on "Checking claude-subscription…".
- Fable and Opus (1M context) do not offer effort "off", because they do not accept it. A chat that you switch to them uses "low". Haiku keeps "off".
- Fable and Opus (1M context) no longer fail when a tool is forced.
- A new chat on the warm spare can use Claude (Sub).

### Fixes

- A chat's first message no longer hangs when the chat uses a local (stdio) MCP server.
- A slash command runs in the chat where you typed it. Before, a command typed in a chat in its own tab could change the chat that was selected in the sidebar.
- A new chat's model picker shows the models at once, not "Loading models…".
- The "Jump to the newest message" button goes away when new content puts you at the bottom. Its tooltip closes when you change tabs.
- Tile names no longer break in the middle of a word. File paths keep their leading "/".
- A finished shell card stops its timer.
- Labyrinth no longer fails on steps of nested sub-agents.
- The Connections strip arrows show how many tiles are hidden.

### Nests

- The link between your desks comes back by itself after VS Code restarts.
- Chats that are open in a window, also stopped chats, show as open on your other desks. Chats that another desk closed no longer stay listed as open.
- The Storage card on your mother base shows the sizes of this desk for each kind of data.
- Storage measures and cleans up in small parts, so a large store does not block the engine.
