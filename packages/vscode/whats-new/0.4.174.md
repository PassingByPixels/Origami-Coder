## What's new since 0.4.155

This update brings everything we built since 0.4.155. The four big changes:

- **Big chats open in about a second**, and long chats no longer pause.
- **Nests** (off by default): start a chat on one computer and continue it on another.
- **Artifacts**: your agent can make a page, a plan or a report for you, with every version kept.
- **Your Claude subscription** (experimental): use it as a model, with all of Origami's tools.

### Big chats open fast, and stay fast

- A chat now opens with its newest messages first. Our largest test chat (151 MB, 16 sub-agents) opened in about 36 seconds before. Now it opens in about 1 second, with 0.2 GB of extra memory instead of 4.2 GB.
- While a chat opens, a large crane shows "Loading chat history" in the middle of the chat panel. With reduced motion on, the crane does not move.
- Older messages load when you scroll up, or when you click "Load earlier messages". The message you read does not move.
- In a long chat, the pause at the end of a reply or during compaction was several seconds. Now it is about 0.1 to 0.3 seconds.
- A new chat starts faster: about 0.15 seconds instead of about 1 second (with nine providers).
- Export and Undo load the older part of a chat when they need it. Export shows its progress.
- This work did not change what Origami sends to the model, so your prompt cache works as before.

### Nests: one chat on all your computers

Nests joins your computers (your "desks") through the Origami relay. You can start a chat on one desk and continue it on another. Nests is off until you turn it on in the Agent Manager, under Nests. Before that, nothing connects to the relay.

- **Add a desk** with a QR code or a key you paste. A key is for one desk only and works for 10 minutes. Both desks show the same 6-digit code: check it, then click Accept.
- **Your data stays private.** The relay sends only encrypted data, has no accounts and stores nothing. The Security card in the Nests view tells you how this works, and links a guide to run your own relay.
- **Here | Nest** in the sidebar. Nest is one list of the chats on your other desks, with running chats first and a search box.
- **Continue here** moves a chat to the desk you are at. If a turn still runs on the other desk, you get a copy (a fork), so no work is lost.
- The desk that gave the chat away shows "Continued on" and the name of the other desk, with **View** and **Take back here**. A chat can move between desks many times and stays one chat.
- Your home desk (the **mother base**) keeps a copy of your chats. You can continue a chat even when the desk that wrote it is off.
- New chats and new turns reach your other desks in about 2 seconds.
- **Storage** in the Nests view sets, for each desk, how long each kind of data is kept.
- History, the Agent Manager and Nests now work with no chat open.

### Artifacts: pages your agent makes for you

- An agent can now **publish an artifact**: a page (with its own styles, scripts and pictures), a plan or a report.
- The chat shows an **artifact card** with Open. The first version opens in the VS Code browser once.
- **Every version is kept.** If two agents change the same artifact at the same time, both versions are kept.
- The **Artifacts** pane in the dock lists your artifacts and their versions: Open, Open chat about, Rename, Delete (with Undo) and Show in Explorer. It shows when each artifact and each version last changed, and which desk has it: "mother base" for this desk, the name of each of your other desks, or "another desk" with the start of its id for a desk it does not know.
- Pages are served only on your own computer, in a sandbox.
- With Nests on, the pane also lists the artifacts of your other desks, with a desk chip. Open copies the files to this desk.
- On Windows, a drive letter in a different case no longer hides an artifact. When the engine does not answer, the pane says so instead of showing an empty list.

### Use your Claude subscription (experimental)

- You can use your Claude subscription as a normal model in Origami, with Origami's own tools, sub-agents, undo and Nests. It is off by default.
- Add it from **+ Add connection**, then **Claude (subscription, experimental)**.
- It needs the Claude Code program on this computer, signed in, version 2.1.263 or later. The card tells you what is missing and how to fix it. Refresh checks again, for example after `claude update`.
- Read the notice before you turn it on: Anthropic bills this use at the Agent SDK rate, and its terms limit the use of subscription logins in other products.
- Origami runs the tools itself. The Claude Code program only supplies the model's reply, and your login stays in it.

### Connections and models

- **Refresh**, next to Connections, reloads the model lists of all your providers. A new model shows without a VS Code reload. The lists also check for new models every 5 minutes.
- When you pick a model, Origami now saves only which model is your default. It no longer copies the provider and its model list into your settings file, so an old copy cannot hide new models.
- A one-time clean-up removes an old Claude (subscription) entry that earlier versions saved by mistake. Origami keeps a backup of your settings file, and does not change an entry you edited yourself.
- The OpenCode Go tab lists every model the gateway serves.
- New controls use the Origami tooltip, not the plain browser tooltip: Refresh, the connection tiles, the find bar and the sub-agent transcript header.

### Sub-agents

- A sub-agent transcript opens at the newest reply.
- The sub-agent drawer lists every sub-agent of the chat at once, also the old ones.
- The sub-agent drawer no longer shows a finished sub-agent as running. A sub-agent that you resume shows its newest state, and Stop moves it to its end state.
- A sub-agent that stops while items on its own todo list are still open gets one reminder to continue, so you do not have to resume it by hand.
- Origami now trims old tool output in batches, not a little at every step. A sub-agent that continues its work can then use its cached prompt again. In our tests, uncached tokens fell by 59 to 79%, and prompts were 14 to 21% larger.
- A transcript that you open in its own tab no longer stays on "Loading transcript…".
- Sub-agent rows show an estimated cost.

### Fork, find and the chat

- **Fork** is a new button next to second opinion. It makes a copy of the chat, so you can try a different direction. The original chat gets no message. A typed `/btw` now only forks.
- A fork that you open again shows the sub-agents of the original chat, up to the point of the fork.
- **Find** has two modes: LOADED (what is on screen, fast) and ALL (the whole chat). Next and Previous now go to every match, also a match inside a closed tool card or thought.
- A message that you send while the chat's engine starts now waits, and goes out when the engine is ready, in the order you sent it. Other chat actions, such as Fork, also wait. If the engine does not start, a warning card tells you why and gives you Retry. Your message is not lost.
- The "Jump to the newest message" button hides when you are back at the bottom, however you got there. While you follow a running turn, the chat stays at the newest message, also when the panel changes size. Only a scroll of the chat stops the follow. This applies to the main chat and to sub-agent transcripts.
- A file path with spaces links as one path, also in code, in quotes and in markdown links.
- A screenshot of about 4 MB or more no longer fails with "invalid base64". It goes to the model.
- A small send button next to Stop lets you add a message while a turn runs.
- When you close a chat, you have 4 seconds to click Undo.
- A "Retrying" card changes to "Recovered" when the model continues.
- The context breakdown card has a pin and a trend line of the last 20 readings.

### Prompt cache

- Labyrinth tells you why each cache miss happened: for example a model change, compaction, or a long pause.
- A cache dot next to Vision shows if the cache of the current chat is warm or cold.
- Origami keeps the cache of OpenAI models warm too.

{{shot:labyrinth-causes|Labyrinth with the cause of each cache miss.}}

### A more reliable engine

- Each step now takes one file snapshot instead of three: about 60% less wait per step.
- Undo is safer. It never deletes a file that was there before the turn.
- The session store grows much more slowly.
- A provider or tool server that does not start tries again after a short pause, instead of staying failed until a restart.
- A permission or question prompt no longer hangs when something fails.
- Goal mode stops at a hard usage limit and tells you when it can continue.
- A local model near the end of its context window no longer repeats the same error.
- The engine log rotates at 10 MB.

### Smaller changes

- A **Settings** item in the Agent Manager holds the settings that were in Insights.
- Crons and Loops are now one item: **Schedules**.
- The Ember theme has darker surfaces, with better contrast.
- The branch pill shows the state of your worktree: changes, ahead and behind.
- This What's new window now shows only for a public release, as one summary.
