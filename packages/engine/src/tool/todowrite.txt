Create and maintain a structured task list for the current coding session. Tracks progress, organizes multi-step work, and surfaces status to the user.

## Use it by default
Create a todo list at the start of any task with more than one or two steps, before your first other tool call. Skip it only for single-step requests or pure questions. When in doubt, use it.

The list is the PLAN, not a log. Write the shape of the whole job first, then work it. When new instructions arrive, capture them in the list.

## When NOT to use
Skip when:
- The work is a single, straightforward task (or <3 trivial steps)
- The request is purely informational or conversational
- Tracking adds no organizational value

## States
- `pending` - not started
- `in_progress` - actively working (one STEP at a time, and the wave above it)
- `completed` - finished successfully
- `cancelled` - no longer needed

## Waves and steps
A plan has two levels, and the `depth` field carries them.
- `depth` 0 is a WAVE: one phase of the work. The waves in order are the plan.
- `depth` 1 is a STEP of the wave above it. A step has its parent's `depth` + 1, and comes DIRECTLY AFTER that parent in the list.
- Maximum depth is 3. Two levels is the normal shape.
- Write every wave when you start. Add the steps you can already name, and add more to a later wave as you learn them.
- Keep exactly one STEP `in_progress`. Its wave is `in_progress` with it. Close a step when its check passes. Close a wave when its steps are closed.
- The list is replaced WHOLE on every call, so re-send each item's `depth` every time you rewrite it -
  including after a summary or a context reset, where the list you are shown carries the nesting as
  indentation only

```json
[
  { "content": "Ship the export button", "status": "in_progress", "priority": "high", "depth": 0 },
  { "content": "Wire the click handler", "status": "completed", "priority": "high", "depth": 1 },
  { "content": "Write the file", "status": "in_progress", "priority": "high", "depth": 1 },
  { "content": "Run the suite", "status": "pending", "priority": "high", "depth": 1 },
  { "content": "Document the new flag", "status": "pending", "priority": "low", "depth": 0 },
  { "content": "Update the README", "status": "pending", "priority": "low", "depth": 1 }
]
```

Use `depth` for structure. Do NOT encode structure in the `content` text with numbering
prefixes ("1a", "1.2", "Step 1 -") or leading dashes and spaces: those are read as part of the
task name, so the list renders flat with the numbering showing through as noise.

A parent's own status is yours to set and is not derived from its children, with ONE limit: a parent
sent as `completed` while any task under it is still `pending` or `in_progress` is recorded as
`in_progress` instead. Finish those sub-tasks, or mark the ones you dropped `cancelled`, then close
the parent.

## Rules
- Update status in real time; don't batch completions
- Mark `completed` only after the required work is actually done, including any required verification. Never based on intent.
- Keep exactly one STEP `in_progress` while work remains. Its wave is `in_progress` with it.
- If blocked or partial, keep it `in_progress` and add a follow-up todo describing the blocker
- Preserve user-provided commands verbatim (flags, args, order)
- Items should be specific and actionable; break large work into smaller steps

## Examples

Use it:
- "Add a dark mode toggle and run the tests" -> multi-step feature + explicit verification
- "Rename getCwd -> getCurrentWorkingDirectory across the repo" -> grep reveals 15 occurrences in 8 files
- "Implement registration, catalog, cart, checkout" -> multiple complex features

Skip it:
- "How do I print Hello World in Python?" -> informational
- "Add a comment to calculateTotal" -> single edit
- "Run npm install and tell me what happened" -> one command
